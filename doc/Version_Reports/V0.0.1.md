## 3. SISTEMAS PRINCIPALES

### 3.1 Service Locator Pattern

**Descripción:** Implementa el patrón Service Locator para inyección de dependencias centralizada.

**Clase:** [ServiceLocator.cs](SoR_Project/Assets/Scripts/Core/Services/ServiceLocator.cs)

```csharp
public static class ServiceLocator {
    private static readonly Dictionary<Type, object> _services = new();
    
    public static void Register<T>(T service, bool overwrite = false);
    public static T Get<T>();
    public static void Reset();
}
```

**Uso:**
```csharp
// Registro en CarneroGameInstaller
ServiceLocator.Register<TimeManager>(timeManager);
ServiceLocator.Register<ProvinceManager>(provinceManager);

// Obtención en cualquier parte
var timeManager = ServiceLocator.Get<TimeManager>();
```

**Ventajas:**
- ✅ Acceso global a servicios críticos
- ✅ Fácil de testear (se puede resetear)
- ✅ Desacoplamiento entre sistemas
- ✅ Registro dinámico durante Awake()

### 5.1 SaveSystem - Persistencia JSON

**Clase:** [SaveSystem.cs](SoR_Project/Assets/Scripts/Save&Seeds/Services/SaveSystem.cs)

**Características:**
- Serialización JSON con **Newtonsoft.Json (Json.NET)**
- Soporte para múltiples tipos de datos (GameData, MetaData, SettingsData)
- Automáticamente guarda el estado de Seeds para carga determinista

```csharp
public static class SaveSystem {
    private static string BasePath => Application.persistentDataPath;
    
    public static event Action OnGameSaved;
    public static event Action OnGameLoaded;
    public static event Action OnGameDataCleared;
    
    public static bool IsFileExist<T>() where T : class, IData, new();
    public static void Save<T>(T data) where T : IData;
    public static T Load<T>() where T : class, IData, new();
    public static void Clear<T>() where T : IData, new();

```

#### 5.1.1 Flujo de Guardado

```csharp
SaveSystem.Save<GameData>(GameDataService.Current);

// 2. Serializar con Json.NET (Formatting.Indented)
// 3. Escribir a Application.persistentDataPath/player_save.json
// 4. Lanzar evento OnGameSaved
```

#### 5.1.2 Flujo de Carga

```csharp
var data = SaveSystem.Load<GameData>();
```

### 7.2 DataFactory - Creación de Instancias

**Clase:** [DataFactory.cs](SoR_Project/Assets/Scripts/DataSystem/Utils/DataFactory.cs)

**Objetivo:** Crear instancias completas de estructuras de datos con inicialización automática de campos.

```csharp
public static class DataFactory {
    public static T Create<T>() where T : class, IData, new() {
        T data = new T();
        
        // Inicializar automáticamente campos que sean clases
        foreach (FieldInfo field in typeof(T).GetFields(...)) {
            if (field.FieldType.IsClass && 
                field.FieldType.GetConstructor(...) != null) {
                field.SetValue(data, Activator.CreateInstance(field.FieldType));
            }
        }
        return data;
    }
}
```

**Uso:**
```csharp
var newData = DataFactory.Create<GameData>();
// Automáticamente: 
// - new RunData()
// - new TimeManagerData()
// - new ParametersData()
```

### 10.1 Shader Graph: PoliticalMapLayer

**Ubicación:** `Assets/Shaders/PoliticalMapLayer.shadergraph`

**Funcionalidad:**

```
Inputs:
├─ _mapColorTex (Texture2D)      // Textura colorMap de provincias
├─ _selectedColor (Color)         // Color de provincia seleccionada
├─ _isSelected (int)              // 0 = no hay selección, 1 = hay

Processing:
├─ Samplear colorMap en UV
├─ Comparar color leído con _selectedColor
├─ Si coincide y _isSelected=1:
│   └─ Aplicar brillo/outline (feedback visual)
├─ Si no coincide:
│   └─ Mostrar color normal
└─ Renderizar frontera (detectación de cambios RGB)

Output:
└─ Color final para renderizar [RGBA]
```

**Parámetros Materiales:**

```
material.SetTexture("_mapColorTex", colorMap)
material.SetColor("_selectedColor", selectedColor)
material.SetInt("_isSelected", 1 or 0)
```

**Funcionamiento:**

1. **Detección de Provincias:** Cada píxel del colorMap representa una provincia
   - Color único = identidad de provincia
   - Usado en MapInteractionHandler para raycast

2. **Feedback de Selección:**
   - Shader resalta la provincia seleccionada
   - Se actualizan materiales en tiempo real

3. **Frontera Visible:** El shader puede detectar cambios de color adyacentes
   - Útil para visualizar límites entre provincias

## 13. HERRAMIENTA CSV TO SCRIPTABLEOBJECT

### 13.1 Descripción General

La herramienta **CSVImporter Tool** (ubicada en [CSVImporter.cs](SoR_Project/Assets/Scripts/Core/Editor/CSVImporter.cs)) permite importar datos masivos desde CSV a ScriptableObjects de forma automatizada.

**Ubicación en Editor:** `Tools > CSV to ScriptableObjects`

### 13.2 Componentes

#### 13.2.1 CSVImporter Class

```csharp
public class CSVImporter {
    public static string[,] ImportCSV(String path) {
        string[] lines = File.ReadAllLines(path);
        int rows = lines.Length;
        int cols = lines[0].Split(",").Length;
        
        string[,] result = new string[rows, cols];
        // Parsing lína por línea, celda por celda
        return result;
    }
}
```

Funcionalidad:
- Leer archivo CSV
- Parsear cada línea (separador: `,`)
- Retornar matriz `string[,]` con los datos

### 13.3 Características Principales

#### 1. 📂 Importación Genérica por Reflection

```csharp
// Soporta CUALQUIER clase con herencia de ScriptableObject
// sin modificar el código de la herramienta

var soType = typeof(SO_Province); // O cualquier otro SO
var soInstance = ScriptableObject.CreateInstance(soType);
```

**Ventaja:** Una sola herramienta para 100+ tipos de SO.

#### 2. 🔄 Mapeo Inteligente Cabeceras → Campos

```
CSV:
    provinceId, provinceName, provincePopulation
    
SO_Province:
    public string provinceId;
    public string provinceName;
    public int provincePopulation;
    
✅ Mapeo automático por nombre (case-insensitive)
```

**Ventaja:** El orden de columnas en CSV no importa.

#### 3. 🧩 Soporte de Tipos Complejos

| Tipo | Ejemplo | Conversión |
|------|---------|-----------|
| **Primitivos** | `int`, `float`, `string`, `bool` | Direct |
| **Enums** | `CSV: "Capital"` → `ProvinceType.Capital` | Parse(ignora case) |
| **Arrays** | `"10;20;30"` → `int[] { 10, 20, 30 }` | Split `;` |
| **Listas** | `"a;b;c"` → `List<string> { "a", "b", "c" }` | Split `;` |
| **Referencias SO** | `"MapTemplate_Test"` → `SO_MapTemplate` | Buscar por nombre |

### 13.4 Flujo de Importación

```
┌─────────────────────────┐
│ Seleccionar CSV         │
│ (Tools > CSV to SOs)    │
└──────────┬──────────────┘
           │
┌──────────▼──────────────┐
│ Seleccionar tipo SO     │
│ (SO_Province, etc)     │
└──────────┬──────────────┘
           │
┌──────────▼──────────────┐
│ Parsear CSV             │
│ (CSVImporter.ImportCSV) │
└──────────┬──────────────┘
           │
┌──────────▼──────────────────────────┐
│ Para cada fila (excepto cabecera):  │
│                                    │
│ ├─ Obtener ID único                │
│ ├─ ¿Existe SO con ese ID?          │
│ │  ├─ Sí: Load y actualizar campos │
│ │  └─ No: CreateInstance nuevo     │
│ │                                  │
│ └─ Mapear campos CSV → SO por nombre
│    ├─ Detectar tipo del campo      │
│    ├─ Convertir string CSV al tipo │
│    └─ Asignar al campo             │
└──────────┬──────────────────────────┘
           │
┌──────────▼──────────────┐
│ Guardar todos los SO    │
│ (AssetDatabase.Save)    │
└──────────┬──────────────┘
           │
┌──────────▼──────────────┐
│ Importación completada  │
│ (Log de resultados)     │
└──────────────────────────┘
```

✅ **Escalabilidad:** De 10 a 10,000 provincias en minutos

✅ **Sin Errores Manuales:** Eliminación automática de inconsistencias  
✅ **Flexibilidad:** Columnas en cualquier orden  
✅ **Referencias Seguras:** Actualización sin romper links

## 15. PATRONES Y PRÁCTICAS UTILIZADAS

### 15.1 Patrones de Diseño

| Patrón | Clase(s) | Beneficio |
|--------|---------|-----------|
| **Service Locator** | ServiceLocator | Inyección de dependencias centralizada |
| **Singleton (Static)** | GameDataService, SeedRandom, SaveSystem | Acceso global al estado |
| **Factory** | DataFactory | Creación automática de estructuras complejas |
| **Observer** | Action/Delegate events | Desacoplamiento entre sistemas |
| **Template Method** | MapDynamicInitializer | Inicialización estructurada |
| **Component Pattern** | ProvinceInfo, MapInteractionHandler | Composición de comportamientos |

### 15.2 Buenas Prácticas Implementadas

#### 1. **Separación de Datos y Lógica**
```csharp
// Datos (Serializable)
ProvinceData

// Lógica (MonoBehaviour)
ProvinceInfo + ParameterController
```

#### 2. **Inyección de Dependencias**
```csharp
// En lugar de:
private TimeManager _tm = GetComponent<TimeManager>();

// Usar:
private TimeManager _tm = ServiceLocator.Get<TimeManager>();
```

#### 3. **Events para Desacoplamiento**
```csharp
// En lugar de referencias directas:
_timeManager.OnDayPassedEvent += UpdateParameters;
```

#### 4. **Clamp Automático en Propiedades**
```csharp
public float stability {
    get { return Mathf.Clamp(_currentData.stability, -100, 100); }
    set { _currentData.stability = Mathf.Clamp(value, -100, 100); }
}
```

#### 5. **Reflection para Automatización**
```csharp
// DataFactory automatiza creación de estructuras
```

   - La textura debe tener exactamente ese color RGB en las áreas de la provincia

4. **Listo:** ProvinceManager cargará automáticamente

### 17.2 Agregar Nuevo Sistema

1. Crear carpeta en Assets/Scripts/
2. Implementar patrón Manager/Data
3. Crear interfaz si es necesario
4. Registrar en ServiceLocator (CarneroGameInstaller)
5. Hacer observable con Actions/Events
